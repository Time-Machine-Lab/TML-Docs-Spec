name: Architecture_Design_Spec
description: 这是一个指导系统顶层架构设计的契约模板，聚焦于系统的权衡 (Trade-offs)、边界 (Boundaries) 和数据流 (Data Flow)。
methodology: 
  - "裁剪版 4+1 视图: 核心围绕场景视图(+1)驱动，结合逻辑、过程和物理视图。开发视图已剥离至《开发规范模板.md》。"
  - "架构即取舍 (Architecture is Trade-off): 不要堆砌技术名词，重点解释为什么这么设计，不这么设计的代价是什么。"
  - "克制表达: 不要为了画图而画图。如果是单体应用，极简物理和过程视图；如果是微服务，则重点突出过程(时序)和物理(部署)视图。"
out_of_scope:
  - 绝对不要在此讨论“具体的 API 请求参数”或“某一个特定按钮的业务逻辑”（属于需求/API文档）。
  - 绝对不要在此讨论“代码缩进、目录组织或 Git 分支流”（属于开发规范文档）。

## 5. 关键架构决策与权衡 (Design Decisions & Trade-offs)
---
required: true
description: 记录在架构设计过程中做出的重大取舍。
methodology: "使用 ADR (Architecture Decision Record) 模式：背景 -> 决策 -> 理由 -> 后果。"
example: |
  **决策：选择 Redis 而不是 Memcached**
  - **理由**：系统不仅需要简单的 K-V 缓存，还需要使用 ZSet 实现排行榜功能。
  - **权衡/代价**：Redis 的内存碎片管理相对复杂，需要引入额外的监控策略。
---
