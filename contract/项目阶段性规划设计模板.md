---
name: Phase_Plan_Spec
description: 用于交代某一产品/项目在特定阶段内的功能规划、交付形态与成功标准，让团队所有角色（开发、设计、测试、AI Agent）对本期方向形成共识。
methodology:
  - "黄金圈理论：每个功能模块的描述必须遵循 Why（背景与目的）-> What（做什么）-> How it looks（预期效果）的顺序，不允许跳过 Why 直接描述功能。"
  - "金字塔原理：每个模块描述的结论必须是该模块的「一句话核心价值」，后续使用 2-3 个支撑点展开，支撑点之间不得重叠（满足 MECE 原则）。"
out_of_scope:
  - 绝对不包含任何技术选型、架构设计、数据库结构、API 设计或代码实现细节。
  - 不描述具体的任务拆解、工时估算或迭代计划——这些属于工程管理文档的范畴。
---

required: true
description: |
  本章节用于回答一个核心问题：「本期做完后，产品处于什么状态？」

  写作要求：
  1. 结论先行——第一句话必须是一句可感知的「状态描述」，而不是「我们要做 XXX 功能」。
     好：本期结束后，用户可以在平台上一站式生成并下载 AI 视频，无需切换至第三方工具。
     坏：本期的目标是为用户提供 AI 视频生成聚合功能。

## 2. 功能模块规划
---
required: true
description: |
  本章节是文档的核心。每个模块必须从用户视角出发，描述「用户看到了什么、做了什么、得到了什么」，而非系统如何实现。

  写作原则：
  - 黄金圈嵌套：每个模块内部必须按 Why -> What -> How it looks 展开。
  - 禁止堆砌功能点：每个模块聚焦解决一个用户核心诉求，不要把 5 个无关功能塞进一个模块。
  - 边界前置：每个模块最后必须明确「本期不包含什么」，防止后续执行时范围悄悄膨胀。
---

### 2.1 [模块 A 名称]
---
required: true
description: 本模块要解决的第一个用户核心诉求。
methodology: "黄金圈理论 + 用户故事三要素（角色-场景-目标）"
example: |
  ### 2.1 AI 视频生成工作流

  **模块一句话价值**：让用户在一个界面内完成从输入描述到下载视频的全部操作。

  **用户视角描述**：
  背景与目的（Why）：用户目前生成一个 AI 视频需要打开 A 网站生成画面、打开 B 网站配音、再打开 C 网站剪辑，整个过程割裂且耗时。模块 A 的目的是把这条路打通，让用户只和一个平台打交道。

  做什么（What）：用户输入一段文案描述，选择视频风格和时长，点击「生成」后，平台自动调用多个 AI 视频生成 API，并行生成结果。

  预期效果（How it looks）：用户进入「AI 视频工作流」页面后，看到一个简洁的输入框和风格选择面板；点击生成后，页面实时展示各 API 的生成进度；生成完成后，用户可以在同一个页面预览所有结果，点击任意一个视频可放大查看；确认满意后，点击「下载」即可获取视频文件。

  **本期不包含**：
  - 视频剪辑（裁剪、添加字幕、音量调整等功能）
  - 生成历史记录和收藏功能
  - 多段视频的拼接能力

## 4. 本期成功标准
---
required: true
description: |
  本章节定义「什么样的结果才算本期成功」，让团队成员和 AI Agent 在执行过程中有一个明确的验收参照。

  写作原则：
  1. 每条标准必须是**可观测、可验证**的结果，而非模糊的方向描述。
  2. 标准分为两类：功能验证标准（模块是否按预期工作）+ 用户体验标准（用户是否真正能完成核心任务）。
  3. 避免使用「提升」「优化」等模糊动词，改用「从 X 变成 Y」的具体描述。

  这些标准是本期交付的最低验收线，不包括性能、稳定性等工程指标。
format_instruction: 使用 Markdown 表格，分为「验收维度 | 成功条件 | 验证方式」三列。
example: |
  | 验收维度 | 成功条件 | 验证方式 |
  | :--- | :--- | :--- |
  | 模块 A 功能完整性 | 用户可在工作流页面完成「输入描述->生成->预览->下载」全流程，无需跳出平台 | 产品走查文档，QA 执行全流程测试用例 |
  | 模块 A 支持 API 数量 | 至少接入 3 个主流 AI 视频生成 API，并可正常生成结果 | QA 对每个 API 执行生成测试，3/3 通过 |
  | 模块 B 效果对比 | 用户输入同一文案后，至少 2 个 API 并行生成并展示对比视图 | 产品走查 |
  | 用户体验完整性 | 一个完全不了解产品的外部用户，参照文档能在 5 分钟内完成首次视频生成 | 可用性测试或内测反馈收集 |
